Advanced Static Cartography in R

Session 2: Designing effective thematic maps

Martijn Tennekes

What makes a map effective?

Design questions

Before writing any code:

  • Message: what should the reader take away?
  • Audience and medium: report, journal, poster, slide? Printed or on screen?
  • Data type: counts, rates, categories, a continuous surface?
  • Visual hierarchy: which elements matter most for the message, and should therefore stand out most?

Principles

  • For a single numeric variable (a univariate map), the two most common map types are the choropleth and the proportional symbol map; which one to use depends on the data:
    • Densities / rates / percentages → choropleth (fill color)
    • Counts / totals → proportional symbols (size)
  • Many other map types exist; several are covered in this course (bivariate maps, glyphs, grid maps, cartograms)
  • Choose a scale (classification) that fits the distribution and the message
  • Choose a color palette that fits the data type (session 3)
  • Make the thematic layer visually dominant; context (borders, basemap, labels) should support it
  • Every legend, title and credit should earn its place

Numeric data: interval scales

Classification styles

The style argument of tm_scale_intervals():

Style Classes based on
"pretty" (default) rounded numbers; n is the preferred number of classes
"equal" equal widths
"quantile" equal number of features per class
"fisher", "jenks" natural breaks (minimize within-class variance)
"sd" standard deviations
"kmeans" k-means clustering of the values
"fixed" manual breaks

The choice of classes may change the message of the map considerably!

Same data, different classification

tmap_arrange(
  tm_shape(NLD_muni) + tm_polygons("income_high",
    fill.scale = tm_scale_intervals(style = "equal")) + tm_title("equal"),
  tm_shape(NLD_muni) + tm_polygons("income_high",
    fill.scale = tm_scale_intervals(style = "quantile")) + tm_title("quantile"),
  tm_shape(NLD_muni) + tm_polygons("income_high",
    fill.scale = tm_scale_intervals(style = "fisher")) + tm_title("fisher"),

Interval labels

  • Classes are intervals, by default closed on the left: [a, b) (interval.closure)
  • By default, labels are disjoint: neat, but they leave gaps between classes
  • interval.disjoint = FALSE: exact, but boundary values seem to belong to two classes
tmap_arrange(
  tm_shape(NLD_muni) + tm_polygons("income_high",
    fill.scale = tm_scale_intervals(style = "equal")) +
    tm_title("interval.disjoint = TRUE (default)"),
  tm_shape(NLD_muni) + tm_polygons("income_high",
    fill.scale = tm_scale_intervals(style = "equal",
      label.format = tm_label_format(interval.disjoint = FALSE))) +
    tm_title("interval.disjoint = FALSE"),
  ncol = 2)

Discuss: in which class is a municipality with 16.215? And with 16.22? Which labels suit your audience?

Fixed breaks

Discussion: choosing breaks

A practical strategy

  1. Start with "kmeans" (or "fisher") or a log scale to see where the natural breaks are
  2. Round those break values to numbers that are easy to read
  3. Use these as custom breaks in the next iteration
tm_shape(NLD_muni) +
  tm_polygons(
    fill = "pop_dens",
    fill.scale = tm_scale_intervals(
      breaks = c(0, 500, 1000, 2000, 3500, 7000),
      values = "brewer.yl_gn_bu"),
    fill.legend = tm_legend("Population per km2"))

Visual hierarchy

What is visual hierarchy?

The ordering of map elements by visual prominence, so that it matches their importance for the message of the map.

  • The most important elements (usually the thematic layer) stand out; context (borders, basemap, labels) recedes
  • Figure–ground: the thematic layer is the figure, the rest the ground
  • Tools: contrast, lightness and saturation of colors, line width, size, font size/weight
  • Layer stacking (drawing order) helps, but is not the same thing: a layer on top can still be visually weak, and a basemap underneath can still dominate

Step 3: palette, title and components

What changed in step 3?

  • A diverging, color-blind friendly palette with sufficient contrast with the black border lines (cols4all::c4a_gui())
  • Legend title removed, because a map title is used instead
  • Title placed above the map (tm_pos_out()); legend top left
  • Compass, scale bar and credits grouped at the bottom left, where there is empty space
  • Components placed inside the frame, so the map itself can be larger
  • A larger left inner margin (inner.margins) creates room for the legend and components

Positioning: shortcut

tm_shape(NLD_muni) +
  tm_polygons("grey85", col = "grey60") +
tm_compass(position = c("left",  "top")) +
tm_scalebar(position = c("right", "bottom")) +
tm_credits("(c) CBS", position = c(0.2, 0.2))
  • lower case: inside the frame, with a small offset
  • upper case, e.g. c("RIGHT", "BOTTOM"): tight against the frame
  • numeric: (0,0) = bottom left, (1,1) = top right

Positioning: shortcut

Positioning: tm_pos_in() and tm_pos_out()

  • The plot area is a 3×3 grid; the centre cell is the map itself
  • tm_pos_in() → inside the map frame; tm_pos_out() → one of the 8 surrounding cells
  • cell.h, cell.v (which cell), pos.h, pos.v (where in the cell), just.h, just.v, align.h, align.v

Grouping components

tm1 = tm_shape(NLD_muni) +

tm1 +

Exporting

tmap_save()

tmap_save(tm, filename = "world.png", width = 7, height = 4, dpi = 300)
tmap_save(tm, filename = "world.pdf", width = 7, height = 4)
  • Pixel based (png, jpg, tiff) or vector based (pdf, eps, svg) — vector based is preferred for print
  • width/height: values < 50 are inches, otherwise pixels
  • Only one dimension given? The other follows from the aspect ratio of the map
  • dpi: ≥ 144 for web (retina displays), 300 or 600 for print
  • More on scale and exporting in session 12

Recap

  • Match the map type to the data: densities, rates, percentages → choropleth; counts → symbols
  • The scale (classification) changes the message: choose it deliberately
  • Legend content in the scale, legend appearance in tm_legend()
  • Build a visual hierarchy: the thematic layer visually dominant, context subordinate
  • Position and group components with tm_pos_in(), tm_pos_out(), tm_components()
  • Further reading: scales | legends | layout | positions | export
